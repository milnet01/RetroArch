# play_feature_delivery hosts two JNI callbacks declared `JNIEXPORT void
# JNICALL Java_...`.  cppcheck 2.20 mis-classifies the JNICALL macro and emits
# `missingReturn` for the function-end brace.  The functions are genuinely

# --- S13: SHA1Digest output parameter misclassified as input -----------------
# libretro-common's SHA1Digest signature is
#   void SHA1Digest(const uint8_t *data, size_t len, uint8_t digest[20]);
# The third arg is an output buffer (the function writes the 20-byte digest).
# cppcheck has no annotation for output-only params and reports the buffer as
# uninitialised at the call site.  RVZ encryption fills a per-block hash array
# block-by-block; each cell is written before any reader runs.
legacyUninitvar:cheevos/cheevos_rvz.c:1753

# --- S14: wl_list_for_each loop variable initialised by macro ----------------

# from the list head before the first iteration; the declared `od` is never
# read uninitialised.  cppcheck 2.20 doesn't trace through the macro and emits
# uninitvar for `od->output` inside the loop body.  Both Wayland output
# enumeration sites pattern-match the same FP.
